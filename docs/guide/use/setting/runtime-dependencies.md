# 插件第三方依赖

某些插件需要额外的 npm 包。Certd 会在运行到插件时按需安装，并缓存到数据目录下的 `data/.runtime-deps`。容器部署需保留原有数据目录挂载，否则缓存和其它 Certd 数据都会丢失。

默认情况下 Certd 会探测 npm 镜像连通性，优先尝试可访问的镜像并在安装失败后继续尝试其它候选地址。安装过程运行在 Certd 服务进程可访问的网络环境中。

## 依赖安装失败的排查

1. 从流水线执行日志找到失败任务和报错的第三方包名。
2. 在 Certd 服务日志中搜索「第三方依赖安装」或「动态依赖加载失败」，检查安装使用的镜像和末尾的 pnpm 输出。
3. 判断失败发生在安装前还是安装后。网络错误和超时检查 Certd 主机或容器的 DNS、出站网络及代理。模块安装成功、导入时报错时，保留完整模块错误，问题可能来自插件或包本身。
4. 修复网络后重新运行任务。已损坏的缓存导致模块仍无法导入时，进入「系统管理 → 插件管理」，选择「清理第三方依赖缓存」，确认后重启 Certd，再运行任务重新安装。

清理缓存会删除 `data/.runtime-deps` 下的安装内容，不会卸载插件。清理后须重启 Certd，运行任务时重新下载所需依赖。若仍然失败，收集完整安装日志、插件名、包名和 Certd 版本。

安装依赖可能需要几十秒。等待时不要重复启动同一任务。依赖目录可能由多个插件共用，勿只删除其中一个包的目录。
