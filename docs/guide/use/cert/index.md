# 证书申请与托管

在 Certd 中，流水线负责取得证书、部署证书和定时检查。可以从证书颁发机构申请，也可以使用已有证书。

| 证书来源 | 从哪里开始 |
| --- | --- |
| 申请并自动续期 | 在流水线列表点击 **创建证书流水线**，选择颁发机构和验证方式。 |
| 从服务器或对象存储取证书 | 点击 **添加更多流水线 → 拉取证书部署**。 |
| 手动提供证书和私钥 | 点击 **已有证书托管**。 |

后两种方式的文件要求、更新行为和排错见 [已有证书托管与远程拉取](./hosting.md)。

## 创建申请流水线

1. 在流水线列表点击 **创建证书流水线**，输入要写入证书的域名。需要同时覆盖 `example.com` 和 `*.example.com` 时，请分别填入。
2. 选择 **证书颁发机构**。第一次申请普通域名可从 Let's Encrypt 开始。选择需要 ACME 账号的机构时，先生成对应授权。详见 [ACME 账号、EAB 和自定义颁发机构](./acme.md)。
3. 配置 **验证方式**。以实际托管解析记录的 DNS 服务商为准，完整选项见 [域名验证](./validation.md)。公网 IPv4 或 IPv6 地址请按 [IP 证书申请](./ip.md) 配置。
4. 保存后打开流水线，在申请任务后添加部署任务。部署任务的 **域名证书** 选择申请任务输出的 **域名证书**，再填写目标授权和部署位置。
5. 手动运行一次，检查申请和部署日志，并访问目标站点确认它提供新证书。第一次验证成功后，配置定时触发器，例如每天检查一次。是否重新申请由申请任务的到期更新天数决定。

### 密钥算法和 CA 配置

申请任务默认使用 RSA 2048。需要 ECC 证书时，在 **密钥算法** 选择 EC 256、EC 384 或 EC 521；如果目标设备只支持传统 RSA，可保留 RSA 选项。SSL.com、Let's Encrypt、Google 和自定义 ACME 的可用算法与证书配置以该 CA 的 Directory 能力为准。

## 首选证书链

申请任务的 **首选证书链** 可在 CA 提供多个证书链时选择希望使用的链。日常使用可保留默认值。如果旧设备遇到信任链问题，先确认服务端部署了完整证书链，再测试备用选项。

| 颁发机构 | Certd 提供的选项 |
| --- | --- |
| Let's Encrypt | ISRG Root X1、ISRG Root X2 |
| Google | GTS Root R1、GlobalSign。GlobalSign 链更长，部分旧设备兼容性更好。 |

## 首次运行失败

- **找不到验证方式。** 使用 **自动选择** 前，先在 **设置 → 域名管理** 保存对应域名的验证配置。详见 [域名验证](./validation.md#自动选择与域名导入)。
- **DNS 记录还未生效。** 检查 DNS 授权、记录名称和解析结果。确认只是传播慢时，再增加申请任务的 **等待解析生效时长** 或 **检查解析重试次数**。详见 [DNS 验证排错](./validation.md#排查-dns-验证失败)。
- **申请偶尔失败。** 申请任务的 **证书申请失败重试次数** 用于重试可恢复的下单错误，重试间隔为 30 秒。配置不匹配、账号错误或 CA 限流时，按日志修正后再运行。
- **申请成功，但站点仍使用旧证书。** 查看部署任务日志和目标资源，检查证书是否绑定到站点、监听器或域名，以及目标服务是否需要重载。
