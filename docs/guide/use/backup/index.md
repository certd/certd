# 数据库备份与恢复

以下步骤适用于默认的 SQLite 部署。使用 MySQL、MariaDB 或 PostgreSQL 时，使用数据库的备份工具，并同时保存 Certd 的数据目录和部署配置。[多数据库配置](../../install/database.md)

## 手动备份

停止 Certd 后复制完整数据目录，再启动服务。完整目录包括数据库、首次启动生成的授权加密密钥和上传文件。Docker 部署以 Compose 中映射到 `/app/data` 的宿主机目录为准，默认是 `/data/certd`。源码部署的数据目录默认是 `packages/ui/certd-server/data`。同时保存 Compose 或源码环境配置，便于在新机器恢复运行。

## 自动备份

<!-- 截图占位：数据库备份流水线任务配置，遮盖远程主机、对象存储桶和授权标识。 -->
专业版管理员可创建空白流水线，添加「数据库备份」任务。选择备份方式、存放目录和保留天数，按需开启「附加上传文件」。本地方式默认保存到数据目录下的 `certd_backup`，远程方式可使用对象存储或文件传输服务。

### 用 SCP 存到另一台服务器

1. 在「授权管理」创建并测试 SCP 授权，确认连接用户能写入备份目录。
2. 在备份任务中选择「OSS 上传（推荐）」，将「OSS 类型」设为 SCP，再选该授权并填写远端目录。
3. 手动运行一次，到远端确认 ZIP 文件能下载和解压。成功后添加定时触发器和失败通知。

备份文件包含敏感数据。请把备份保存到仅有授权人员可读的位置，并单独保存完整数据目录备份。

## 恢复

1. 停止 Certd，并保留当前数据目录的备份。
2. 恢复原数据目录和原部署配置。使用流水线生成的 ZIP 时，先解压，再把备份中的 SQLite 文件恢复到服务所用的数据库路径，默认文件名为 `db.sqlite`。如压缩包包含上传目录，也一并恢复。授权加密密钥应来自同一实例的数据备份。
3. 先在隔离环境启动恢复后的实例，检查登录、证书和授权，再启用定时任务。若授权读取失败，核对加密密钥文件是否与该数据库配套。
