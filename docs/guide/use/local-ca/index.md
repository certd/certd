# 本地 CA

本地 CA 用于给内网系统、测试环境和内部服务签发 TLS 证书。与 Let's Encrypt 等公共 CA 不同，本地 CA 的根证书不会被操作系统或浏览器默认信任，**必须把根 CA 证书安装到所有客户端/服务器的信任库**。

本地 CA 支持两级结构：根 CA → 中间 CA → 叶子证书。只有中间 CA 可以签发叶子证书。

> 入口：使用系统管理员账号登录，进入 **系统管理 → 本地 CA**。

## 1. 基本概念

| 概念 | 说明 |
| --- | --- |
| 根 CA | 信任锚，只用于签发中间 CA 和生成 CRL；不能直接签发叶子证书。 |
| 中间 CA | 实际签发证书的 CA；可就绪 ACME 服务、分配授权、轮换。 |
| 叶子证书 | 签发给业务域名/IP 的证书。 |
| Base URL | 写入证书 CRL 与 ACME Directory 的对外地址；留空时使用当前站点地址。 |
| CRL | 证书吊销列表，客户端可据此判断证书是否被吊销。 |

## 2. 生成本地根 CA

1. 在本地 CA 页面点击 **生成**。
2. 填写名称、Common Name（如 `Example Internal Root CA`）。
3. 选择密钥类型（RSA 2048/3072/4096 或 ECDSA P-256/P-384）、有效期和用途（服务端/客户端/双向）。
4. **最大签发天数**：根 CA 会限制其下中间 CA 的叶子证书最长有效期。
5. **允许签发域名**：可选。留空表示不限制；填写后，其下中间 CA 只能签发这些域名或其子域名。
6. **Base URL**：可留空。留空时使用当前访问 Certd 的站点地址；如果后续要修改，已签发证书中的旧地址仍会指向旧地址。
7. 保存后请立即导出并妥善备份根 CA 私钥（导出操作需要二次验证）。根 CA 私钥丢失将无法恢复。

## 3. 创建中间 CA

1. 在根 CA 行点击操作列的 **新建中间 CA** 图标（根 CA 专属）。
2. 填写名称和 Common Name。
3. **有效期**不能超过根 CA 的剩余有效期；**最大签发天数**和**允许签发域名**不能超过根 CA 的限制。
4. Base URL 自动继承根 CA，中间 CA 创建后不可修改。
5. 中间 CA 创建后可继续配置权限、启用 ACME、签发证书。

### 轮换中间 CA

当中间 CA 密钥需要更换时，使用 **轮换**：

- 生成新密钥和新的中间 CA，自动复制原 CA 的授权、管理员与策略；
- 旧中间 CA 变为只读并停止签发，已签发证书仍然有效，直到过期或重签；
- 已配置的 ACME 颁发机构自动指向新 CA；
- 旧 CA 不能重新启用、编辑或再次轮换；
- 轮换与直接签发、禁用、吊销、归档互斥，不会出现旧 CA 在轮换过程中继续签发。

## 4. 权限管理

只有中间 CA 可以授权。打开中间 CA 的 **管理 → 权限管理**：

- **用户模式**：授权指定用户，其全部项目均可使用该 CA。
- **项目模式**：授权指定项目，项目内全部用户均可使用（需要商业版企业模式；非企业模式不显示该选项）。
- 已授权的用户/项目会保留在下拉中但置灰并标记“已授权”，避免重复授权；撤销后恢复可选。
- 添加和移除授权都需要二次验证（动态验证码或 Passkey）。
- 移除授权时可选择 **同时停用已分配的 ACME 账户**：账户立即停用，无法继续签发或续期；对应授权名称追加“（已停用）”，用户可自行删除。

> 根 CA 不显示权限管理页签。

## 5. 启用 ACME 服务

只有中间 CA 可以启用 ACME。启用后 Certd 会为该 CA 提供标准 ACME Directory：

```
<BaseURL>/api/acme/<CA ID>/directory
```

同时系统会在「流水线设置 → 证书颁发机构」中自动生成一个带 `【中间CA】` 标记的本地颁发机构条目。

### 5.1 访问模式

| 模式 | 适用场景 | 访问控制 |
| --- | --- | --- |
| 本地 ACME | Certd 内部流水线使用 | 只认可服务端下发的内部 Token；外部请求默认拒绝（仅回环地址可访问）。标准模式遗留的 IP 白名单/Basic/自定义头不会影响内部流水线。 |
| 标准 ACME | 外部 ACME 客户端或需要完整门禁 | 支持 IP 白名单、Basic 认证、自定义请求头、客户端 IP 来源和可信代理 CIDR。 |

### 5.2 标准模式访问控制

- **IP 白名单**：留空时默认仅允许内网地址；填写后只允许命中规则（裸 IP/CIDR/IPv4 通配符），最多 50 条。
- **Basic 认证**：必须使用 HTTPS 对外地址，HTTP 下会拒绝，避免用户名密码明文传输。
- **自定义请求头**：外部客户端必须携带指定的头名和值，最多 10 条。
- **客户端 IP 来源**：
  - `X-Forwarded-For`：按可信代理链解析；
  - `socket`：直接使用 TCP 连接地址；
  - `header`：从指定请求头读取（仅可信代理来源时采信）。
- **可信代理 CIDR**：只有来自这些代理的转发头才被信任，防止伪造 IP 绕过白名单。

### 5.3 内部 Token

本地模式使用内部 Token 鉴别 Certd 自身流水线请求。Token 由服务端通过 `LocalCaGetter` 下发，**不会通过 HTTP 返回给浏览器**。

如怀疑 Token 泄漏，可在访问控制页执行 **轮换内部 Token**。轮换后旧 Token 立即失效，流水线会自动获取新 Token。

## 6. EAB 凭证

本地 ACME 使用 EAB（External Account Binding）注册 ACME 账户。EAB 与 CA 授权相互独立。

### 6.1 用途模式

| 用途 | 说明 |
| --- | --- |
| 本地 ACME | 管理员使用该 EAB 注册账户并分配给用户/项目；创建后不显示 HMAC Key，用户无需接触 EAB。 |
| 标准 ACME | 交付给外部 ACME 客户端；创建后仅显示一次 KID 与 HMAC Key，请立即保存。 |

### 6.2 类型

- **普通**：按标准 ACME 流程进行域名所有权验证。
- **特权**：跳过域名所有权验证（ACME Challenge），但**仍受 CA 域名范围、最大有效期、CA 状态等全部限制**。特权 EAB 需要所有者权限和二次验证。

### 6.3 可注册账户数

设置该 EAB 最多可注册的 ACME 账户数：

- `0` 表示不限制；
- 只能调高或调整为 0，不能低于当前已注册账户数；
- 仅统计账户注册次数，不影响账户后续签发/续期次数。

### 6.4 分配账户

管理员可在 EAB 行点击 **分配账户**：

1. 选择用户或项目（企业模式仅项目）；
2. 填写邮箱，系统使用 EAB 注册 ACME 账户；
3. 可勾选自动授权该目标使用 CA；
4. 注册成功后，目标用户/项目在流水线中即可选用该本地 ACME 颁发机构。

若注册失败，系统会回滚本次新增/恢复的授权，不留下额外的签发权限。

### 6.5 泄漏处置

如果 EAB 泄露，打开 EAB 详情确认 **泄漏情况**，执行 **泄漏处置**：

- EAB 被不可恢复地禁用；
- 勾选的可疑账户被停用；
- 这些账户已签发的证书被吊销；
- 未勾选的账户保留可用。

请随后创建新 EAB 供后续注册。

## 7. 签发证书

### 7.1 通过流水线（推荐）

创建流水线，添加 **本地CA证书申请** 任务：

| 签发方式 | 说明 |
| --- | --- |
| 本地CA直接签发 | 不经过 ACME Challenge 所有权验证，但**仍受 CA 域名范围、最大有效期和 CA 状态限制**；需在 CA 设置中开启“本地直签”。 |
| 本地ACME服务 | 使用标准 ACME 协议；选择已授权的中间 CA 颁发机构；特权 EAB 可跳过域名所有权验证。 |

本地 ACME 模式下，CA 由所选颁发机构自动确定，无需再次选择；ACME 账号与颁发机构必须匹配。

### 7.2 外部 ACME 客户端

使用 **标准 ACME** 用途的 EAB：

1. 在 CA 的 ACME 访问控制中配置标准模式门禁；
2. 客户端使用 Directory URL `<BaseURL>/api/acme/<CA ID>/directory`；
3. 使用 KID + HMAC Key 完成 EAB 注册。

外部客户端必须满足该 CA 的 IP/Basic/自定义头门禁；仅本地模式会拒绝所有外部请求。

## 8. 客户端信任根 CA

1. 在根 CA 操作列选择 **查看 / 导出**，导出根 CA 证书（`.pem`/`.crt`）。
2. 将根证书安装到所有需要访问业务服务的客户端、服务器、浏览器的受信任根证书列表。
3. 如果中间 CA 发生轮换，客户端仍需信任原根 CA；新中间 CA 由同一根 CA 签发，无需重新分发根证书。

## 9. 吊销与归档

- **吊销中间 CA**：将该中间 CA 标记为不可恢复吊销，并递增根 CA CRL，后续不能重新启用。
- **归档 CA**：要求 CA 已禁用（中间 CA 还需已吊销），且其签发证书均已吊销或过期；归档后不可修改。
- 已轮换的中间 CA 只读，不能编辑、管理或重新启用，但仍可查看证书与执行必要的归档。
- 已归档 CA 不再出现在选择器中，但其历史证书仍可用到过期。

## 10. 安全建议

- 根 CA 私钥务必离线备份，导出操作需要二次验证。
- 不要将本地 ACME 标准模式直接暴露到公网；确需暴露时务必启用 IP 白名单、Basic 或自定义头。
- 定期检查 EAB 泄漏状态；发现泄漏立即处置并更换 EAB。
- 轮换中间 CA 前确认旧 CA 证书仍被客户端信任到过期；旧 CRL 地址需持续服务。
- 所有高风险操作（导出私钥、轮换、吊销、分配账户、修改访问控制）都需要动态验证码或 Passkey。

## 11. 常见问题

**Q：创建流水线时 CA 下拉为空或提示“请选择本地CA”？**

- 确认中间 CA 已启用 ACME；
- 确认当前用户/项目已被授权使用该 CA；
- 确认该 CA 未被禁用、吊销、轮换或归档；
- 刷新页面后重新选择本地 ACME 颁发机构。

**Q：客户端提示证书不受信任？**

- 根 CA 证书未安装到客户端信任库；
- 或客户端连接的是新中间 CA，但根证书未更新（同一根 CA 轮换时无需更换根证书）。

**Q：外部 ACME 客户端 403？**

- CA 处于本地模式时外部请求会被拒绝；
- 标准模式下检查 IP 白名单、可信代理 CIDR、Basic 认证和自定义头。

**Q：轮换后旧 CA 还能使用吗？**

- 旧 CA 已只读且停止签发，已有证书继续有效到过期；请让流水线自动指向新 CA 并完成重签。
