如果您是第一次升级certd版本，切记切记先备份一下数据    
很多人docker不太会配置，数据目录没有映射出来，升级导致数据丢失
```
# docker-compose.yaml配置
- /data/certd:/app/data   #  请务必确保 /app/data 这个路径没有改动，固定写死
```

:::

## 重要兼容变化

跨多个版本升级时，检查旧流水线、API 调用端和自定义插件是否涉及下列变化。

| 版本 | 升级前需要检查的配置 |
| --- | --- |
| v1.38.0 | 部分插件实现移入服务端。测试自定义插件的模块引用，按现行导出调整引用路径 |
| v1.39.0 | API 响应消息字段由 `msg` 改为 `message`。跨版本客户端可同时兼容两个字段 |
| v1.39.13 | 腾讯云「更新证书（ID 不变）」已下架。按目标服务替换任务，例如使用「腾讯云－部署证书至 CLB」 |
| v1.42.0 | 证书申请任务移除了 `certZip` 输出。界面下载时仍会生成 ZIP，自定义插件可用证书对象和 `CertReader.buildZip()` 生成压缩包 |
| v1.44.0 | 旧的 ACME 反向代理配置迁移到「系统设置 → 流水线设置 → 自定义 ACME 管理」。升级后检查相应颁发机构的代理配置 |
| v1.45.5 | 企业模式按 OpenKey 绑定项目，非企业模式禁止指定项目 ID。核对调用方使用的密钥及权限范围 |
| v1.45.6 | Lego 证书申请任务暂停执行。先确认 JS 版支持所用 DNS 提供商和验证方式，再在原流水线替换申请步骤，并让部署步骤引用新任务的证书输出 |
| v1.47.2 | 暂停扫描触发的自动 IP 封禁，仍可在安全监控中心查看风险并手动封禁 |

升级后检查登录、证书仓库、授权和一条代表性的流水线。运行前确认选的是测试目标，或评估实际部署会影响哪些站点。
